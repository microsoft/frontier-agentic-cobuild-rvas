What the creator can design

Bring the first task you want users to complete, in a new or existing application. Azure Solution Architect defines that journey and designs the architecture. The app doesn't need AI. The creator compares plain code with no model, a fixed workflow, a single model call, and an agent, and recommends the simplest one that does the job.

Whatever you build, the path is the same: agree on it, delegate the build, verify the result. The examples below are illustrations, not customer results or deployment templates.

Application shapes

Most applications take one of these shapes, and many combine several. None needs AI. The products shown are examples. Discovery checks whether they fit, connect to your systems, and are available to you.

Web apps and APIs

Let users or other systems create, read, and update business records: portals, line-of-business apps, back-office tools, public APIs. Decide who signs in, what each role may change, and what happens when a request starts work that takes longer than the call.

Example options
Azure App ServiceManaged hosting for web apps and APIs, from code or a container.
Azure SQL DatabaseA managed relational store for transactions and reporting on operational data.

Microservices

Split a large domain into services that separate teams deploy and scale on their own. Decide where each boundary sits, which service owns which data, and how services stay consistent without sharing a database. If one team owns the product, a modular monolith is cheaper to run.

Example options
Azure Container AppsContainerized services without managing Kubernetes.
Azure Kubernetes ServiceA managed cluster, when you need Kubernetes APIs or cluster-level control.

Event-driven integration

React to business events such as an order placed, a file arrived, or a status changed. Decide who owns each event schema, how consumers handle the same event twice, and where failed events go. Use a synchronous API when the caller needs an answer straight away.

Example options
Azure Event GridPush notifications about state changes to many subscribers.
Azure Service BusBusiness messages and work queues with ordering, retries, and dead-lettering.

Durable business workflows

Run a process that spans minutes to months, with waits, approvals, timers, and retries: onboarding, claims, procurement. Decide who owns the process state, how it resumes after a failure, and how completed steps get undone when a later one is rejected.

Example options
Azure Logic AppsConnector-based workflows that people maintain in a visual designer.
Azure Functions with Durable FunctionsCode-defined workflows with persisted state and recovery.

Batch and data processing

Move and reshape data on a schedule: nightly imports and exports, pipelines into analytics, reporting. Decide which system holds the record for each dataset, who may use each layer, and how a failed run restarts without duplicating data.

Example options
Azure Data FactoryScheduled pipelines that copy and transform data across sources.
Microsoft FabricPipelines, a lakehouse, and reporting on one analytics platform.

Modernize an existing application

Extend, move, or gradually replace a system you already run. Decide what to keep, which part moves first, and how data stays in sync while old and new run side by side. Microsoft's Strangler Fig pattern replaces a system one route at a time.

Example options
Azure MigrateDiscover and assess what runs today before you plan the move.
Azure API ManagementA front door that routes each API to the legacy or the new implementation.

AI capabilities you can add

Add AI to any shape above when the journey needs it. These are the forms it usually takes. The creator still compares each one with plain code and a fixed workflow first.

Knowledge assistants

Help users find information they're allowed to see, and cite where it came from. Decide who owns each source, how fresh it must be, and what happens when sources conflict or have nothing to say. A fixed lookup may not need an agent.

Example options
Azure AI SearchSearch and retrieval for an application-owned assistant.
Microsoft Copilot StudioA platform-managed agent grounded in configured knowledge sources.

Agents that use business tools

Investigate a task, then prepare or perform approved operations. Decide what is read-only, what needs approval, who is authorized, and how retries avoid doing the same business action twice.

Example options
Azure Logic AppsConnector-based business workflows.
Foundry Agent ServiceAn agent that selects configured tools. Enforce business authorization separately.

Document and media processing

Turn incoming files into structured results. Decide the output schema, when a person reviews, how errors get corrected, and where results go next. This is often a fixed pipeline with no chat interface.

Example options
Azure Document IntelligencePrebuilt or custom extraction models for known document types.
Azure Content UnderstandingAnalyzers for unstructured documents or mixed-media inputs.

Voice and audiovisual experiences

Use speech or video when the task needs it. Decide how users interrupt, correct or leave, and cover privacy and accessibility. An avatar or generated video doesn't make something an agent.

Example options
Azure SpeechCompose speech recognition and synthesis with your application logic.
Voice Live APIA speech-to-speech API within Azure Speech, rather than a separate product.

Coordinated specialist agents

Split the work across agents only when one agent can't do it reliably. Coordination costs something, so decide up front how agents hand off work, what each can access, what state they share, and what happens when they disagree or fail. Microsoft's orchestration guidance recommends the simplest design that meets the requirement.

Example options
Foundry Agent ServiceA managed agent runtime. Verify support for the selected coordination pattern.
Microsoft Agent FrameworkCode-defined orchestration. Choose hosting separately, including Foundry when appropriate.
