Agree before you delegate.

Agents made code cheaper to produce. They didn't make understanding cheaper. This talk explains why, and what to do about it.

Prompting is fast. Agreeing is the work.

Agents made code cheaper to write. They didn't make it cheaper to know what to write. Without agreement up front, an agent builds the most plausible reading of the brief, and the team finds the gap after the build. Barry Boehm showed in 1981 that errors cost more the later they surface. Agents get you to that late stage in hours.

Pure vibe coding

Kai Lentit's sketch Senior Engineer tries Vibe Coding (6 minutes) exaggerates for laughs, but the failures are familiar. The agent ignores written rules, changes things nobody asked for, and the bill keeps growing. Nobody agreed what done looks like, so there is nothing to check the output against.

Plan mode helps, but a plan is still prose

Net Ninja's Using Plan Mode (5 minutes) shows the better version. The agent asks clarifying questions and writes a task list before it builds. Then the presenter skips reading the plan, approves it, and the agent carries on in autopilot. For a small quiz feature that is fine, and he says plan mode is overkill for a change that narrow. For a real system, nobody can check a long plan, and approving it is not agreement.

Approve something people can challenge

Diagrams, wireframes and a task plan can be looked at, questioned and corrected before any code exists. C4 models, UML, swimlanes and wireframes come from fifty years of software engineering. We don't invent a new way to agree. Agents let us produce the established ones in minutes. We reinvent everything to reinvent nothing.
