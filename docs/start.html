Two repository skills prepare a co-build. Idea Forge finds a use case when you only know the customer. Use-Case Mapper shows which parts of a known use case the kit helps build.

Idea Forge

You know the customer or industry, but not what to build first. The skill researches public sources and ranks about ten ideas.

Idea Forge hands its top idea to Use-Case Mapper, so both routes end with the same map.

Route 1

Idea Forge

Use it at the start of an engagement when you know the customer or industry, but not the first useful AI proof. It turns public research and customer signals into ranked, right-sized ideas across all current tracks.

Not an architecture approval. The scenario conversation still checks source ownership, access, environment, operating model, and evidence.

Five-minute idea funnel

1

Prepare the prompt

Bring the customer or business-unit name, industry, and any region, segment, or pain points you are allowed to use.

2

Run the skill

Customer Activity-Forge researches public sources only, marks gaps instead of guessing, and proposes about ten achievable ideas.

3

Select one direction

Prefer an idea with a narrow user, an owner, a safe representative sample, and a first evidence case the customer can review.

4

Map the idea

The skill runs Use-Case Mapper on the top idea, so you get the same parts-to-modules map as Route 2.

What to prepare

Required

  • Customer name or business unit.
  • Industry or sector.

Helpful if known

  • Region or customer segment.
  • Allowed pain points or public signals to verify.
  • Any data, content, or process boundary already discussed.

Keep out

  • Confidential account-plan or CRM details.
  • Unapproved customer data.
  • Claims the team cannot cite or validate.

What Idea Forge produces

Research summary

Three to five sentences with public-source citations and explicit coverage gaps.

Ranked ideas

About ten ideas ranked by customer fit, achievable first proof, and differentiation. Each names the tracks it draws on.

Scenario handoff

The top idea gets a pre-filled handoff, with assumptions marked for the customer to confirm.

Module map

The top idea's parts mapped to modules, with a build order and the gaps.

Route 2

Use-Case Mapper

Use it when the customer already knows what they want. The skill reads every scenario manifest, splits the use case into the steps it needs, and maps each step to specific modules. Uncovered work stays in the map.

A partial match is not coverage. If a module covers half a step, the map says what the team still has to build.

From use case to session plan

1

Describe the use case

Say what starts it and what the finished result is. Add users, systems, and data owners if you know them.

2

Run the skill

It splits the use case into five to eight steps and marks each one Covered, Adapt, or Not covered.

3

Review it with the customer

Confirm the assumptions, the open platform choices, and who owns each uncovered part.

4

Plan the first slice

Build the few parts that prove the main outcome first, in module order.
