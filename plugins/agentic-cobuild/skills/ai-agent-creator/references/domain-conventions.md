# Domain conventions

Read the application's existing glossary and relevant ADRs before proposing terms
or decisions. Follow its established layout, including `GLOSSARY.md` or
`GLOSSARY-MAP.md`, when present.

If the application has no convention, use root `CONTEXT.md` for agreed domain
vocabulary and `docs/adr/` for consequential decisions. Create these records only
when discovery resolves a term or decision. Missing files are not errors and do
not require placeholders.

Keep architecture requirements in `docs/architecture/specification.md`. Link to
domain records instead of duplicating their definitions. Explain conflicts with
existing ADRs before proposing a replacement.
